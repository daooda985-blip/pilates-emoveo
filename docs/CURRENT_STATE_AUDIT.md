# Аудит текущего состояния Pilates by emoveo

Дата проверки: 31 октября 2026  
Назначение: зафиксировать фактическое состояние перед созданием общей оболочки. Это аудит кода, не полный браузерный QA.

## 1. Что уже существует

- `index.html` — основная публичная страница, содержит HTML, встроенные CSS-стили и большую часть интерфейсного JavaScript.
- `js/generator.v1.js` — отдельный модуль генерации и проверки плана.
- `data/exercise-library.v1.json` — каталог из 40 упражнений.
- Планировщик имеет поля продолжительности, уровня, основного фокуса и оборудования.
- Генератор формирует три этапа: разминка, основной комплекс и растяжка.
- В черновике есть редактирование порядка, замена, добавление и удаление упражнений.
- Есть копирование текстового плана.
- В карточках отображаются техника, дозировка, дыхание, варианты упрощения/усложнения и меры предосторожности.
- Упражнения могут содержать ссылку на демонстрацию; для непроверенных видео отображается соответствующая отметка.

## 2. Что пока отсутствует или ограничено

- Нет отдельной рабочей панели Dashboard.
- Навигация пока ведёт только к маркетинговым секциям страницы.
- Нет отдельной страницы или полноценного интерфейса каталога упражнений.
- Нет сохранения занятий между перезагрузками страницы.
- Нет пользовательских шаблонов и экрана управления ими.
- Нет отдельного раздела настроек приложения.
- Нет профилей клиентов, групп, расписания и аналитики.
- Основной CSS и большая часть UI-логики находятся внутри `index.html`; это увеличивает сложность дальнейшего развития.
- Генератор и каталог уже разделены по файлам, но остальные границы модулей ещё не оформлены.

## 3. Что важно сохранить

- Существующий планировщик и его поля.
- Генерацию трёх обязательных этапов.
- Проверки времени, уровня и оборудования.
- Редактирование упражнений.
- Копирование плана.
- Существующую библиотеку и её метаданные.
- Явное отображение дефицита времени вместо искусственного увеличения дозировки.

## 4. Рекомендуемый порядок изменений

1. Создать общую навигацию и рабочую оболочку, не переписывая генератор.
2. Добавить Dashboard и понятные входы в существующий Planner.
3. Добавить базовый экран Exercise Library поверх существующего JSON-каталога.
4. Добавить каркасы Templates, Clients, Schedule, History и Settings с честными статусами «в разработке».
5. Вынести стили и интерфейсные модули постепенно, после проверки каждого шага.
6. Затем внедрить local-first хранение, экспорт и импорт данных.

## 5. Ограничения аудита

Проверены исходники и структура данных, но этот аудит сам по себе не подтверждает полное тестирование в браузере, на мобильном устройстве или после публикации GitHub Pages. Такие проверки выполняются отдельно после внесения изменений.


## 6. Дополнительная проверка интерфейса — 31 октября 2026

Проведён статический аудит актуальной версии после внедрения общей оболочки.

### Исправлено в коде

- На узких экранах навигация рабочего пространства сворачивается в кнопку «Меню разделов».
- Кнопка связана с навигацией через `aria-controls` и `aria-expanded`.
- Меню закрывается после выбора ссылки, клавишей Escape и при возвращении к ширине экрана больше 700 px.
- Добавлены видимые состояния фокуса для ссылок, кнопок, полей ввода, списков и раскрываемых элементов.
- Удалён устаревший текст на главной странице, который утверждал, что план не сохраняется автоматически; теперь описание соответствует локальному хранению настроек, истории и шаблонов.
- Усилена проверка резервной копии: перед восстановлением проверяется вложенная структура этапов и карточек упражнений; повреждённые записи пропускаются, а пользователь видит их количество.

### Проверено автоматически

- Встроенный JavaScript проходит синтаксическую проверку после изменений.
- Импорт отклоняет записи с отсутствующими массивами упражнений или некорректными карточками на уровне структуры.
- В коде присутствуют переключение меню, закрытие по Escape и после выбора ссылки.
- У меню есть доступная связь с кнопкой управления.
- CSS содержит состояния фокуса и правила мобильного отображения.

### Что ещё не подтверждено

- Реальное визуальное отображение на физических экранах и в браузерах.
- Проверка работы с экранным диктором.
- Полный ручной проход по клавиатуре и сенсорному управлению.
- Поведение при ширинах и масштабировании, отличных от заданных CSS breakpoints.

Этот раздел фиксирует проверку исходного кода и автоматические проверки, но не заменяет браузерный QA.


## 7. Проверка истории, шаблонов и восстановления — 31 октября 2026

### Исправлено

- Удаление активной записи истории теперь отсоединяет её от открытого плана. Последующее редактирование создаёт новую запись, а не возвращает удалённую.
- Сохранение истории, создание и удаление шаблонов, сохранение настроек теперь выполняются с откатом состояния интерфейса при ошибке записи в localStorage.
- При неудачном сохранении история и шаблоны повторно отображаются из последнего подтверждённого состояния.
- Импорт проверяет обязательные три этапа занятия, поля параметров, оборудование и безопасный формат идентификаторов записей. Это предотвращает открытие структурно повреждённых планов и внедрение разметки через идентификатор.

### Автоматическая проверка

- Синтаксис встроенного JavaScript и генератора проверен.
- JSON-каталог успешно разбирается.
- Симуляция сохранения после удаления активной записи создаёт новую запись с новым ID.
- Симуляция отказа записи подтверждает возврат прежнего состояния истории.
- Проверены наличие отката для шаблонов и настроек и расширенные проверки импорта.

### Подтверждение пользователя

- Пользователь сообщил, что проверка мобильной версии прошла успешно.

### Ограничения

- Отказ хранилища симулирован программно, а не вызван в реальном браузере на устройстве.
- Полный ручной регрессионный проход по всем сценариям ещё не выполнен.
